## Selected approach

Use explicit shared Flutter tokens and small presentation widgets, then apply them screen by screen. This gives source fidelity and makes ministry extensions consistent. A theme-only change cannot restore card hierarchy; copying React wholesale would discard current functional guarantees. No new runtime dependencies or remote font/image services are needed. Use existing Material outlined equivalents for Lucide symbols (church, home, people, person add, settings, chat bubble, edit, delete, location, phone, calendar, book). Decorative symbols are excluded from semantics; actions retain text or tooltips.

## Responsiveness and accessibility

Check 360x800, 390x844, 768x1024 and 1440x1000 logical pixels, plus 320 wide and text scale 2.0. Allow tiles/actions to wrap and headings to grow; no RenderFlex overflow, inaccessible controls or clipped errors. Long names/congregations must be readable through wrapping or accessible full labels. Safe areas protect Android system bars; scrolling content and floating feedback must clear bottom navigation and keyboard. Touch controls have at least 48x48 targets, keyboard focus is visible, icon actions have Portuguese tooltips, selection/status is conveyed beyond color. Target WCAG AA text contrast; source light status strips may use darker text while retaining source hue.
