# Convert list integration and protected owners

Task 10 supplies `ConvertsPage(scope:, converts:, photos:, congregations:, onScopeRefresh:)`. Inject the actual ConvertRepository and PhotoRepository sharing the same SupabaseGateway/boundary. The root supplies the complete permitted congregation traversal and wires `onScopeRefresh` to the session guard refresh. The scope is a presentation snapshot; PostgreSQL RLS and transactional RPCs remain authoritative. Construct a new page keyed by protected generation after every logout, identity change, resume revalidation or grant loss. Reusing a mounted page with another scope/repository is unsupported, as with the existing forms.

The page traverses every bounded repository page before publishing rows, counts or empty state. It never fabricates an empty list from failed reads. It applies literal case-insensitive name, congregation and visit-status filters over the complete result. Presentation prepares congregation order through the platform pt-BR collator (browser Intl.Collator or Android java.text.Collator), promotes sede first and places unknown congregations last. Each actual congregation ID forms a separate group, including duplicate/equivalent labels; only within that group does server creation instant descending preserve source recency with stable input ties. The synchronous visibleConverts helper consumes this prepared congregation list. Unsupported platform locale channels fail into the recoverable load state rather than approximate or fabricate ordering. Terminal/deleted records do not appear. No subscription, protected persistence or fallback backend is introduced.

Lifecycle controls use existing domain predicates for first visit, 7/30-day visits, 90-day completion and three-visit deviation. Every write uses only the ID and lifecycle action (or ID alone for deletion), with server time/authorization controlling acceptance. `ConvertActions.execute` retains one operation UUID for each failed unchanged ID/action and suppresses duplicate commands per record. Success drops that operation and triggers a full authorized reread. Invalid/stale business state triggers reread; lost permission increments the traversal request generation, latches access denied, clears rows and requests scope refresh. Outstanding pages cannot continue or publish, and outstanding successful commands cannot start another load under that denied snapshot. The root must replace the page after scope revalidation. Shared generation stale results never publish UI changes. Confirmation cancellation sends nothing.

Confirmations are inline AlertDialog widgets and photo enlargement stays inside each card. EditPage uses the approved Task 9 API inside the same protected subtree, with a record/generation key. There are no detached Navigator dialog/sheet routes to outlive root invalidation. Standard Material controls supply immediate feedback, focus and keyboard behavior. Layout wraps cards/actions and scrolls; no custom decorative animation blocks input. Private photos use authenticated metadata/download bytes and Image.memory, ignoring all legacy photo URLs. Brazilian phone normalization distinguishes domestic DDD 55 from an existing country prefix by length and disables invalid numbers.

## Task 19 synchronous invalidation contract

Unmount the entire old ConvertsPage immediately when invalidating the shared boundary, alongside the existing forms. Do not wait for network revalidation. Owners include:

- Page: complete protected record list, pending traversal local pages/cursor, name controller, status/congregation filters, error map, pending IDs, retained EditPage record, lifetime context and request generation.
- ConvertActions: immutable lifetime context, retained failed operation IDs and pending record IDs; page disposal calls clear(). An already submitted server transaction can complete, but no stale completion is published.
- Card: record DTO, authenticated original photo bytes, pending metadata/download closures, photo error, enlargement state and confirmation action. Metadata continuation and byte publication both check context/request identity. Disposal drops bytes and increments request identity.
- Edit subtree: RegisterPage/ConvertForm/ConvertSaveController owners documented in convert-forms.md. The known Android picker/resume coordination requirement remains with Task 19.
- Flutter image cache: root must synchronously clear memory/live image entries and enforce a bounded image cache, as documented in data-gateway.md. In-flight Futures can retain immutable snapshots until completion; generation checks suppress continuation/publication.

No live Google OAuth, private Storage HTTP, Android gallery/device, or external WhatsApp application behavior is proven by widget fixtures. Those remain release integration checks. The inherited native PostgreSQL tests exercise actual local SQL separately.
